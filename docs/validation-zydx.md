# 對照驗證：某排盤網站

命例：aaa，男，公曆 2026-10-08 15:57，台北（經度 121.5）。
目的：把坊間排盤網站的輸出當「標準答案」逐格比對，看引擎哪裡對得上、哪裡對不上、對不上是誰錯（4-2、4-3）。

## 結論先講

**對方把 2026 年寒露的時刻寫錯了**（他們：10-08 16:08；實際：10-08 14:29），導致月柱、起運、交運、胎元、命宮、部分神煞整串跟著錯。其餘與月柱無關的格子，兩邊完全一致。

寒露 14:29 的依據：
- 本引擎以太陽視黃經 195° 的瞬間計算（`fortune/calendar/solar_terms.py`），2024、2025 年的寒露與官方年曆一致到分鐘（03:00、08:41）
- 用 ephem 內建的 `next_autumnal_equinox` / `next_solstice` 獨立驗證 2026 秋分 08:05:09、冬至 04:49:59，與本引擎一秒不差
- 14:29 那一刻的太陽黃經 = 194.9999°；16:08 時已是 195.068°

這是課程 4-3「節氣交界」最好的現場素材：**排盤網站也會錯，而且錯在你看不到的地方（它沒給你節氣是怎麼算的）**。

## 這次順便修掉的本引擎錯誤

比對之前，本引擎把**真太陽時**修正後的時刻拿去跟交節時刻比（15:57 + 18 分 = 16:15），這在概念上是錯的：交節是全球同一瞬間，應該用手錶時間比；真太陽時只用來決定時辰與子時換日。這次改正後，這張盤剛好仍是戌月（因為 14:29 早就過了），但換一張出生在交節前 10 分鐘、經度偏東的盤就會錯一柱。已加進標準命例 `zydx_2026_hanlu_edge`。

第二個：對照「命宮庚子」時發現本引擎算出戊子——**五虎遁的位移沒先對 12 取模**，子、丑兩宮（在寅之前）的天干一律錯。同一個 bug 也在紫微引擎的宮干裡：1990-06-15 例的子宮、丑宮原本顯示丙子、丁丑，正確是戊子、己丑；命宮落在子或丑時連五行局都會跟著錯（午時出生者命宮在子，原本錯成水二局，正確是火六局）。已修，加了標準命例 `life_palace_in_zi` 與兩個測試。這是「拿別人的盤逐格對」才會抓到的錯：之前 1990 例的命宮在亥，剛好避開。

## 對課程的意義

1. 「拿網站當標準答案」要先問：它的節氣從哪來？能不能查？不能查的答案不能當標準。
2. 兩套工具對不上時，找一個第三方可驗證的量（太陽黃經）來仲裁，而不是投票。
3. 查表型的東西（納音、空亡、神煞、稱骨）兩邊全對，說明**錯的是推演層的輸入（節氣），不是查表層**——這正是 2-3 四層模型的用法。
